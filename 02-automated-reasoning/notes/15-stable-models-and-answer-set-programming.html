Stable Models and Answer Set Programming

Lecture 15 - 25 November 2026

1 Stable Models and Program Completion

Stable-model semantics gives logic programs a meaning that supports non-monotonic, commonsense-style reasoning. The central issue is the use of negated literals. A conclusion may be accepted because there is no proof of its opposite, but that conclusion may have to be withdrawn when new information becomes available.

This behaviour differs from monotonic reasoning. In a monotonic system, adding premises cannot invalidate an earlier conclusion. The lecture highlights the following characteristics:

  • Negated literals cause a loss of monotonicity.
  • Commonsense reasoning is not monotone.
  • The meaning of a rule is not captured completely by its classical logical implication.
  • If there are no reasons or proofs for believing an atom, one may tentatively believe its negation.
  • Stable-model semantics formalises this intuition through a guess-and-verify construction.

Program completion helps identify logical consequences and atoms that cannot occur in minimal models. The lecture establishes a relationship between stable models and minimal models of the completion.

1.1 A program and its completion

Consider the following program:

p :- p.
q :- p, not s.
q :- not p, not s.
s :- not q.

For an atom appearing in the head of one or more rules, its completion states that the atom is true exactly when at least one of the corresponding rule bodies is true. Applying this construction gives:

Completion of the program

\[ \begin{aligned} p &\leftrightarrow p,\\ q &\leftrightarrow (p \land \neg s)\lor(\neg p\land\neg s),\\ s &\leftrightarrow \neg q. \end{aligned} \]

The first equivalence, \(p\leftrightarrow p\), places no restriction on the truth value of \(p\). The completion therefore admits models in which \(p\) is true even though the rule p :- p. does not provide an independent justification for introducing it.

The lecture identifies two minimal models of the completion, \(\{q\}\) and \(\{s\}\). It also points out that \(\{p,q\}\) is a model, but not a minimal one because it contains the smaller model \(\{q\}\).

Set of atoms Role in the example
\(\{q\}\) A minimal model of the completion.
\(\{s\}\) The other minimal model identified in the lecture.
\(\{p,q\}\) A model of the completion, but not a minimal one because \(\{q\}\subset\{p,q\}\).

The example distinguishes three ideas: being a classical model of the completion, being minimal under set inclusion, and having the support required by stable-model semantics.

1.2 Stable models and minimal models of the completion

Stable models and program completion

Given a program \(P\), every stable model of \(P\) is among the minimal models of the completion of \(P\).

In particular, if \(\operatorname{Comp}(P)\) denotes the completion of \(P\), then each stable model of \(P\) is a minimal model of \(\operatorname{Comp}(P)\).

This is a necessary relationship. It does not state that every model of the completion is stable.

1.3 Encoding the completion for a SAT solver

A SAT solver can find classical models of the formulas in the completion. The lecture considers an equivalence of the form

Typical completion formula

\[ H\leftrightarrow \left( (\ell_1\land\cdots\land\ell_m) \lor (r_1\land\cdots\land r_n) \right), \]

where each \(\ell_i\) and \(r_j\) is a literal.

To obtain conjunctive normal form, the two directions of the equivalence are treated separately. Define

\[ L=\bigwedge_{i=1}^{m}\ell_i, \qquad R=\bigwedge_{j=1}^{n}r_j. \]

The direction \((L\lor R)\rightarrow H\) becomes

First direction

\[ \left(H\lor\bigvee_{i=1}^{m}\neg\ell_i\right) \land \left(H\lor\bigvee_{j=1}^{n}\neg r_j\right). \]

The other direction, \(H\rightarrow(L\lor R)\), becomes one clause for every pair consisting of a literal from \(L\) and a literal from \(R\):

\[ \bigwedge_{i=1}^{m}\bigwedge_{j=1}^{n} \left(\neg H\lor\ell_i\lor r_j\right). \]

Combining the two directions gives the full CNF representation:

\[ \begin{aligned} &\left(H\lor\bigvee_{i=1}^{m}\neg\ell_i\right) \land \left(H\lor\bigvee_{j=1}^{n}\neg r_j\right)\\ &\qquad\land \bigwedge_{i=1}^{m}\bigwedge_{j=1}^{n} \left(\neg H\lor\ell_i\lor r_j\right). \end{aligned} \]

A SAT solver can find models of this CNF formula, but it may also return non-minimal models. In the previous example, \(\{p,q\}\) satisfies the completion even though the smaller set \(\{q\}\) is also a model. Classical satisfiability of the completion is therefore not sufficient to establish stable-model minimality.

1.4 A program with no stable models

Consider the program:

p :- not p, d.
d.

The set \(\{p,d\}\) is a classical logical model when the rules are read as implications. The fact makes \(d\) true, while the body of the first rule is false when \(p\) is true. Nevertheless, the program has no stable models.

Its completion is:

Completion

\[ \begin{aligned} p &\leftrightarrow (\neg p\land d),\\ d &\leftrightarrow \top. \end{aligned} \]

The fact forces \(d\) to be true. The first equivalence then reduces to \(p\leftrightarrow\neg p\), which cannot hold for either truth value of \(p\). The completion has no classical model, and consequently the program has no stable model.

2 Denials and Support

The body of an ASP rule can be understood as a justification for supporting the truth of its head. An atom belongs to an answer set only when it is supported by a rule whose body is true in that answer set.

The lecture stresses one important limitation: an occurrence of not p in a rule body cannot itself support the truth of \(p\).

For example:

p :- not p, d.

This rule does not support \(p\). The only occurrence of \(p\) in its body is under negation as failure. Another rule with head \(p\) could provide support, but this rule cannot do so by itself.

2.1 Replacing an unsupported self-negating rule with a denial

Suppose that \(p\) does not occur in the head of any other rule. From the answer-set point of view, the rule

p :- not p, d.

has the effect of requiring \(d\) to be false. This requirement can be written directly as a denial, also called a constraint:

Denial or constraint 
:- d.

A denial has no head. It rejects every candidate answer set in which its body is true.

The lecture illustrates the transformation with:

a.
p :- not p, a.

The fact requires \(a\), while the second rule does not provide support for \(p\). The program has no stable models. Its denial formulation is:

a.
:- a.

This formulation is inconsistent for the same reason: the fact requires \(a\), while the denial forbids it.

Now consider the choice rule together with the denial:

{a}.
:- a.

The choice rule permits \(a\) to be selected or omitted. The denial removes every candidate that contains \(a\). The only answer set left is the empty set.

3 Stable Models, Answer Sets, and Non-deterministic Choices

A program may have no stable models, exactly one stable model, or several stable models. Stable models are also called answer sets, and programming with the purpose of finding answer sets is called Answer Set Programming, or ASP.

ASP is presented as a declarative programming paradigm for search problems. The lecture mentions applications in combinatorial optimisation, constraint satisfaction and artificial intelligence, and stresses that the expressive power of ASP is known a priori. An ASP program describes the choices and conditions that determine which answer sets are admissible, rather than prescribing a sequence of computational steps. The slide situates this paradigm in Victor W. Marek and Miroslaw Truszczynski’s work, Stable Models and an Alternative Logic Programming Paradigm, and Ilkka Niemelä’s work, Logic Programs with Stable Model Semantics as a Constraint Programming Paradigm.

3.1 Representing truth-tellers and liars

Consider four students: Albert, Bob, Charlie and Dexter. The atom a represents the fact that Albert tells the truth, while na represents the fact that Albert is a liar. Exactly one of these atoms is true. The same convention is used for Bob, Charlie and Dexter.

Student Tells the truth Is a liar
Albert a na
Bob b nb
Charlie c nc
Dexter d nd

Each student has two alternatives. With four students, the number of possible worlds is

Number of possible worlds

\[ 2^4=16. \]

The pair of rules for Albert expresses the choice between the two alternatives:

a  :- not na.
na :- not a.

The complete program is:

a  :- not na.    na :- not a.
b  :- not nb.    nb :- not b.
c  :- not nc.    nc :- not c.
d  :- not nd.    nd :- not d.

Its answer sets contain exactly one atom from each pair: one of \(a\) and \(na\), one of \(b\) and \(nb\), one of \(c\) and \(nc\), and one of \(d\) and \(nd\). There are therefore sixteen answer sets, one for each assignment of truth-teller or liar status to the four students.

3.2 Adding relationships between the choices

The lecture asks what happens when the following rules are added:

a :- b.
c :- nb.

The first rule states that if Bob tells the truth, Albert must tell the truth. The second states that if Bob is a liar, Charlie tells the truth. These rules restrict the combinations that can remain answer sets. The slide poses this as a question and does not provide an enumeration, so no count of the remaining answer sets is asserted here.

3.3 Choice rules as syntactic sugar

The pair of rules

a  :- not na.
na :- not a.

can be written more compactly as the choice rule:

{a}.

This notation allows \(a\) to be selected or not selected. It is the compact form introduced in the lecture.

3.4 Denials revisited with a choice rule

The combination

{a}.
:- a.

contains a choice and a restriction. The choice rule permits both possibilities for \(a\), and the denial eliminates the possibility in which \(a\) is present. Thus the only permitted answer set is \(\varnothing\).

4 Complexity of Stable-Model Existence for Ground Programs

The lecture next studies the computational complexity of deciding whether a program admits at least one stable model.

NP-completeness of stable-model existence

Given a ground program \(P\), deciding whether \(P\) admits an answer set, or stable model, is NP-complete.

A program is ground when none of its rules contains variables. The proof has two parts: membership in NP and NP-hardness.

4.1 Membership in NP

A candidate stable model \(S\) needs to contain only atoms that occur in the ground program. Its size is therefore bounded by the size of the program:

\[ |S|\leq |P|. \]

A nondeterministic polynomial-time procedure can:

  1. Guess a candidate set of atoms \(S\).
  2. Compute the reduct \(P^S\) associated with \(S\).
  3. Compute the fixpoint model \(M_{P^S}\).
  4. Check whether \(S=M_{P^S}\).

The reduct computation, fixpoint computation and final equality check are polynomial in \(|P|\). A candidate can therefore be guessed and verified in nondeterministic polynomial time, establishing membership in NP.

4.2 NP-hardness by reduction from 3SAT

For hardness, the lecture considers the following 3SAT instance:

3CNF formula

\[ \varphi= (A\lor\neg B\lor C) \land (\neg A\lor B\lor\neg C). \]

Call the first clause \(c_1\) and the second clause \(c_2\). The program encodes a truth assignment by choosing exactly one atom for each Boolean variable and its negation:

a  :- not na.    na :- not a.
b  :- not nb.    nb :- not b.
c  :- not nc.    nc :- not c.

Here a, b and c represent the positive assignments to \(A\), \(B\) and \(C\). The atoms na, nb and nc represent their negative assignments.

The clause atoms are derived from the literals that make each clause true:

c1 :- a.
c1 :- nb.
c1 :- c.

c2 :- na.
c2 :- b.
c2 :- nc.

The atom c1 is supported if at least one of \(A\), \(\neg B\) or \(C\) is true. Likewise, c2 is supported if at least one of \(\neg A\), \(B\) or \(\neg C\) is true.

Finally, both clauses are required to hold:

satisfied :- c1, c2.
:- not satisfied.

The first rule derives satisfied when both clause atoms hold. The denial rejects candidates in which satisfied cannot be derived. Consequently, the constructed program admits a stable model if and only if the 3SAT instance is satisfiable.

The construction can be computed in LOGSPACE, as stated in the lecture. It establishes NP-hardness. Together with membership in NP, this proves the theorem.

5 Answer Set Programming and Grounding

ASP is used to encode search problems declaratively. The previous complexity result concerns ground programs, but ASP programs are often written with variables. A grounder instantiates these variables with values from the program’s Herbrand universe, producing a propositional program for the solver.

5.1 The size of a grounding

Let \(H_P\) be the Herbrand universe of a program \(P\). If \(H_P\) is infinite, its grounding can be infinite as well. The lecture therefore assumes that \(H_P\) is finite and writes

Finite Herbrand universe

\[ |H_P|=c. \]

Suppose that \(P\) contains rules \(r_1,\ldots,r_n\), with \(n\leq |P|\). Let \(\alpha_i\) be the number of distinct variables occurring in rule \(r_i\). Each variable can be instantiated with one of the \(c\) elements of the Herbrand universe. The number of possible ground instances of rule \(r_i\) is \(c^{\alpha_i}\).

The total number of ground rule instances is therefore

\[ \sum_{i=1}^{n}c^{\alpha_i}. \]

Let

\[ k=\max_i\{\alpha_i\}, \]

and let \(h\) be the size of the largest rule. The lecture gives the following upper bound on the size of the ground program:

Ground-program size bound

\[ |\operatorname{ground}(P)|\leq n h c^k. \]

The exponential factor comes from the number of possible substitutions for the variables in a rule. If the domain size \(c\) is represented compactly, grounding may require exponential time in the size of the original program. The slide gives p(1..1000) as an example of an implicitly specified range. It also notes that intervals can be used to encode problems outside NP.

5.2 Example: exponentially many ground instances

Consider the following program for large \(n\):

bit(0).
bit(1).

exp(X1, X2, ..., Xn) :-
    bit(X1), bit(X2), ..., bit(Xn).

Every variable \(X_i\) can take either value 0 or 1. The choices are independent, so the rule has

Number of ground instances

\[ 2^n \]

possible ground instances. This demonstrates how a compact non-ground rule can expand into a much larger ground program.

6 The ASP Solving Pipeline and Range Restrictions

The usual ASP architecture separates grounding from search. First, the grounder transforms the program into a ground program. The solver then computes its answer sets.

The ground program \(\operatorname{ground}(P)\) should be finite. To ensure this, the source program must satisfy appropriate range restrictions. The lecture compares the ASP architecture with the MiniZinc pipeline:

\[ \text{MiniZinc} \longrightarrow \text{FlatZinc} \longrightarrow \text{Constraint Solver}. \]

Two exceptions are mentioned: Asperix and GASP, cited in the slide as [DDPR09]. These systems mix grounding and search. The slide notes that this approach has some advantages and many drawbacks, without developing the comparison further in this lecture.

6.1 Domain predicates and strong range restriction

The grounder needs a finite scope for every variable. The general rule introduced in the lecture is:

Strong range restriction

Every variable occurring in a rule must occur as an argument of a domain predicate that occurs positively in the body of that rule.

A program satisfying this condition is called strongly range restricted.

The positive occurrence is important. A variable appearing only inside a default-negated literal is not bounded by that literal.

Consider the examples:

p(X).

q(X,Y) :- r(X), not s(Y).

The fact p(X). contains a variable but has no positive body predicate to restrict its values. In the second rule, X occurs in the positive body literal r(X). It is bounded there if r is a domain predicate. The variable Y occurs only in not s(Y), so that negative literal does not restrict its range. These examples therefore do not satisfy the strong range-restriction condition.

The lecture uses the following working definition of a domain predicate:

  • A predicate defined extensionally by a set of ground facts is a domain predicate.
  • A predicate defined by strongly range-restricted definite clauses is also a domain predicate.

The lecturer recommends stopping at this definition for the course discussion. A wider notion exists in the literature, but it is not introduced here.

7 ASP Tools and Clingo

The lecture distinguishes between the tools that perform grounding and those that compute stable models.

Stage Tools named in the lecture
Grounders LPARSE, DLV Grounder, GRINGO
Solvers SMODELS, CMODELS, DLV Solver, CLASP

SMODELS is identified as the first solver. The DLV system, associated with Vienna and Rende, is equipped with the ASPIDE integrated development environment. The tool used in the course is Clingo, which combines gringo and clasp:

Clingo

\[ \text{Clingo}=\text{gringo}+\text{clasp}. \]

The lecture identifies the University of Potsdam as the development institution and describes Clingo as the fastest tool. This is the characterisation given on the slide. The implementation of the solvers is left for later analysis.

7.1 Installing Clingo

The slide directs students to the Clingo website at https://potassco.org/clingo/. The installation procedure presented uses Anaconda. After installing Anaconda, open the Anaconda terminal and run:

conda create -n potassco -c conda-forge clingo
conda activate potassco

The slide states that this procedure works on any operating system. It also mentions installation on Linux through the usual package-management procedure, without providing further commands.

7.2 Executing an ASP program

Assume that the program is stored in a file named asp.lp. The command shown in the lecture is:

clingo asp.lp n

The final argument n specifies how many stable models the solver should compute. The defaults described in the lecture are:

  • n = 1: compute one answer set. This is the default.
  • n = 0: compute all answer sets.

The lecture also shows how to assign a value to a program constant. For example:

clingo -c n=15 asp.lp

To control which atoms are printed, a program can contain a #show directive:

#show p/2.

This asks Clingo to print atoms based on predicate p with arity two that hold in the answer set or sets. Without a #show declaration, all atoms are printed.

The lecture then moves to a practical experimentation phase titled “Play with Clingo”.

8 Exercises

The lecture concludes with three exercises. They are retained as tasks, without adding solutions that were not part of the supplied material.

8.1 Reachability in a directed graph

Assume that the input is a directed graph represented by facts of the form:

arc(a1,b1).
arc(a2,b2).
arc(a3,b3).
% ...

The constants denote vertices. Define the predicate reach/2 so that reach(X,Y) holds if and only if there is a path from vertex X to vertex Y in the graph.

8.2 Functions, injections, surjections and bijections

Assume that the predicates domain/1 and range/1 define extensionally the domain \(A\) and range \(B\) of a function. Define a predicate f/2 representing a function from \(A\) to \(B\), so that the answer sets return all such functions. Then define predicates for:

  • inj: a one-to-one, or injective, function;
  • surj: an onto, or surjective, function;
  • bij: a bijection, if one exists.

The slide notes that != is a built-in operator that may be used.

8.3 Finding a maximum

Assume that the input consists of facts of the form:

p(n1).
p(n2).
p(n3).
% ...

where each \(n_i\in\mathbb{N}\). Define a predicate q that holds for the maximum value \(n_i\) for which p(n_i) holds. The lecture notes that < is built in.
