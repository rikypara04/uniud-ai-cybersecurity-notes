Reachability, Proper Complexity Bounds, and Complements

Lecture 14 - 17 November 2026

1 Relations among time and space classes

The lecture begins by collecting the consequences of the deterministic and nondeterministic simulations introduced previously. For a suitable time bound \(f(n)\), deterministic computation is a special case of nondeterministic computation, and a computation using at most \(f(n)\) steps cannot visit more than \(O(f(n))\) tape cells. Therefore,

\[ \operatorname{TIME}(f(n)) \subseteq \operatorname{NTIME}(f(n)) \]

and

\[ \operatorname{TIME}(f(n)) \subseteq \operatorname{SPACE}(f(n)). \]

The same deterministic-as-nondeterministic observation yields

\[ \operatorname{SPACE}(f(n)) \subseteq \operatorname{NSPACE}(f(n)). \]

The previous lecture established that a nondeterministic machine running in time \(f(n)\) can be simulated deterministically in time exponential in \(f(n)\). When the bound is polynomial, this gives the class-level containment

\[ \mathrm{P} \subseteq \mathrm{NP} \subseteq \mathrm{EXP}. \]

Combining the time-to-space observation with the definitions of the aggregate classes also gives

\[ \mathrm{P} \subseteq \mathrm{PSPACE} \subseteq \mathrm{NPSPACE}. \]

The lecture uses these containments as a bridge from general definitions to the concrete reachability problem.

2 Directed reachability

For a directed graph \(G=(V,E)\) and two vertices \(u,v\in V\), the reachability decision problem asks whether a directed path from \(u\) to \(v\) exists. As a language,

\[ \mathrm{REACHABILITY} = \left\{ \langle G,u,v\rangle \ \middle|\ \text{there is a directed path from }u\text{ to }v\text{ in }G \right\}. \]

Standard graph-search algorithms show that reachability is in \(\mathrm{P}\). A breadth-first or depth-first search is polynomial on ordinary programming models, and those models are polynomially related to Turing machines. A conventional search, however, stores visited vertices to prevent repeated exploration, so its straightforward space consumption is polynomial rather than logarithmic.

2.1 A nondeterministic logarithmic-space algorithm

A nondeterministic machine can decide reachability without storing the complete set of visited vertices. The machine keeps only:

  • the current vertex \(w\);
  • a nondeterministically generated candidate successor \(w'\);
  • a counter recording how many edges have been traversed.

The procedure is:

  1. store \(u\) as the current vertex;
  2. if the current vertex is \(v\), accept;
  3. nondeterministically generate a vertex \(w'\);
  4. scan the read-only graph encoding and verify that \((w,w')\in E\);
  5. if the edge does not exist, reject that branch;
  6. otherwise replace \(w\) by \(w'\), increment the counter, and repeat;
  7. reject the branch once the counter exceeds \(|V|-1\).

The counter is essential. Without it, a branch could repeatedly traverse a cycle and never halt. If a path from \(u\) to \(v\) exists, a simple path exists as well, and a simple path contains at most \(|V|-1\) edges. Hence stopping after this many traversals does not remove every accepting branch.

A vertex name requires

\[ O(\log |V|) \]

bits, because vertices can be numbered from \(1\) to \(|V|\). The counter up to \(|V|-1\) has the same asymptotic size. Only a constant number of such quantities is stored.

Reachability in nondeterministic logarithmic space

Directed reachability can be decided using nondeterministic logarithmic working space:

\[ \mathrm{REACHABILITY}\in\mathrm{NSPACE}(\log n)=\mathrm{NL}, \]

where \(n\) is the length of the graph encoding.

The lecture leaves the best deterministic-space algorithm as a problem to reason about separately.

3 Encoding a graph and measuring its input size

Complexity is measured against the length \(n\) of the input encoding, not directly against the informal quantity \(|V|+|E|\). The lecture therefore makes the relationship explicit.

Assume that

\[ V=\{1,2,\ldots,|V|\}. \]

An adjacency-list-style binary encoding may contain:

  1. a binary representation of \(|V|\);
  2. separators;
  3. for each edge \((i,j)\in E\), the binary encodings of \(i\) and \(j\).

Up to separators and constant factors, its length is

\[ n = O\!\left(\log |V|+2|E|\log |V|\right). \]

Since a directed graph has at most \(|V|^2\) edges,

\[ n = O\!\left(|V|^2\log |V|\right). \]

Conversely, the encoding explicitly contains vertex identifiers, so \(\log |V|\) is bounded by the input length. This is why the working-space estimate \(O(\log |V|)\) may also be written as \(O(\log n)\) for the representation under discussion.

Representation Approximate size Appropriate case
List of encoded edges \(O(|E|\log |V|)\) Sparse graphs
Adjacency matrix \(\Theta(|V|^2)\) bits Dense graphs

An adjacency matrix places its Boolean rows consecutively on the tape. The two encodings are polynomially related, but practical space and access costs differ. For example, an empty graph has an extremely short edge-list representation, while an adjacency matrix still contains \(|V|^2\) zero entries.

4 Why complexity bounds require restrictions

The lecture then moves from Chapter 2 to the study of hierarchy results. Earlier definitions treated a function \(f\) as a time or space bound with very few restrictions. This raises a fundamental question: which functions are reasonable resource bounds?

A non-computable function is clearly unsuitable. It would be strange to classify terminating computations using a bound whose value cannot itself be computed. Computability alone is still insufficient, however. Pathological computable bounds can create large gaps in which increasing the apparent resource bound does not enlarge the corresponding complexity class. This motivates restricting attention to proper functions.

The lecture previews two contrasting phenomena:

  • gap results can make two apparently different bounds define the same time class for specially constructed functions;
  • hierarchy results show strict increases between suitable bounds when the bounds satisfy the properness conditions.

For familiar proper bounds, this leads to an infinite hierarchy rather than a collapse at one fixed polynomial degree. In particular, no fixed \(k\) can satisfy

\[ \mathrm{P}=\operatorname{TIME}(n^k), \]

because a larger polynomial time bound yields languages outside that particular level while still remaining inside \(\mathrm{P}\).

5 Proper functions

A proper function is required not only to be computable, but to be computable within resources comparable to the value that it will later serve as a bound for.

Let

\[ f:\mathbb{N}\to\mathbb{N}. \]

The first requirement is monotonicity:

\[ n\le m \quad\Longrightarrow\quad f(n)\le f(m). \]

The second requirement is witnessed by a deterministic I/O Turing machine \(M_f\) that computes \(f(n)\) from any input of length \(n\). The output is written in unary, so the final output tape contains a distinguished symbol repeated exactly \(f(n)\) times.

Proper function

A function \(f:\mathbb{N}\to\mathbb{N}\) is proper when:

  1. \(f\) is non-decreasing;
  2. there exists a deterministic \(k\)-tape I/O Turing machine \(M_f\) such that, on every input \(x\) of length \(n\):
    • \(M_f\) writes \(f(n)\) in unary on its output tape;
    • all working tapes are blank again at termination;
    • its running time is \(O(f(n)+n)\);
    • the space used on each working tape is \(O(f(n))\);
    • the exact time and working-space usage depend only on \(n\), not on the particular string \(x\).

The term \(+n\) in the time bound is necessary because the machine may need to read an input of length \(n\). It is especially important when the same definition is used for sublinear space bounds such as \(\log n\). The function \(\log n\) should qualify as a proper space bound even though the input still requires linear time to scan.

Writing \(f(n)\) in unary also has a purpose: the output acts as a yardstick containing exactly one mark per unit of the bound. A later simulation can erase one mark for every simulated step.

The familiar bounds mentioned in the lecture are proper, including constants, logarithms, polynomials, exponentials with polynomial exponents, and factorial-type functions. Proper functions are also stable under the common arithmetic operations and compositions used to build standard bounds.

6 Precise machines

A machine with a worst-case time bound may use different amounts of time on different inputs of the same length. For example, insertion sort has linear best-case time and quadratic worst-case time. The lecture introduces precise machines to eliminate this input-dependent variation.

Precise I/O Turing machine

A \(k\)-tape I/O Turing machine \(M\) is precise if there exist functions \(t\) and \(s\) such that, for every input \(x\), the machine performs exactly

\[ t(|x|) \]

steps and uses exactly

\[ s(|x|) \]

working space. These quantities depend only on the input length, not on the particular input contents.

Precision from a proper time bound

If an I/O Turing machine decides a language in at most \(f(n)\) steps and \(f\) is proper, then there is a precise I/O Turing machine deciding the same language in

\[ f'(n)\in O(f(n)) \]

steps.

6.1 Unary padding idea

Run the machine \(M_f\) for the proper bound and obtain \(f(n)\) unary marks. Then simulate the language decider \(M\), erasing one mark for each simulated step. If \(M\) terminates early, erase the remaining marks before halting. This second phase therefore always lasts exactly \(f(n)\) steps, independently of the input contents.

The lecture explicitly notes a technical caveat: the padding argument directly makes the running time precise, but the simultaneous space-precision requirement needs an additional adjustment. This missing space detail is not developed further in the lesson.

7 Complements of complexity classes

For a language \(L\subseteq\Sigma^*\), its complement is

\[ \overline{L}=\Sigma^*\setminus L. \]

In a deterministic decider, complementing the language is straightforward: exchange the final answers \(\mathrm{yes}\) and \(\mathrm{no}\). The machine uses the same time and space, so deterministic time and space classes are closed under complement:

\[ L\in\operatorname{TIME}(f(n)) \quad\Longrightarrow\quad \overline{L}\in\operatorname{TIME}(f(n)), \]

and

\[ L\in\operatorname{SPACE}(f(n)) \quad\Longrightarrow\quad \overline{L}\in\operatorname{SPACE}(f(n)). \]

The same argument does not work for nondeterministic machines. A nondeterministic machine accepts when there exists at least one accepting branch:

\[ N(x)=\mathrm{yes} \quad\Longleftrightarrow\quad \exists\text{ an accepting branch on }x. \]

Negating this statement gives a universal condition:

\[ N(x)\ne\mathrm{yes} \quad\Longleftrightarrow\quad \forall\text{ branches, the final answer is no}. \]

If a computation tree for \(x\in L\) contains both a yes leaf and a no leaf, swapping all leaf labels still leaves a yes leaf. The complemented machine would therefore accept \(x\) even though \(x\notin\overline{L}\).

Key distinction for nondeterministic complements

Existential acceptance cannot be complemented merely by exchanging yes and no leaves. The negation of “there exists an accepting branch” is “every branch rejects,” not “there exists a rejecting branch.”

This observation motivates the separate study of complements of nondeterministic complexity classes, but the lecture stops after identifying why the deterministic complementation trick fails.
